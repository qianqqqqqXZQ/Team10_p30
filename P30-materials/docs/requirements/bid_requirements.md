# GRP 竞标书（Bid）要求

本文根据课程提供的竞标与提交说明整理，供小组撰写竞标书、确定志愿顺序及准备提交材料时使用。文中将官方要求与本组准备事项分开列出。

## 1. 竞标目的与项目选择

- 每个小组应阅读可选项目的项目简介（project briefs），确定最希望参与的三个项目。
- 每组最多准备并提交 **3 份独立竞标材料**，每份对应一个所选项目，并按志愿顺序排名。
- 竞标书的核心目的是：**说服项目提出者将项目交给本组完成**。

本组目前意向项目为 **19、21、30**，该列举顺序**不代表志愿排名**。最终提交前需另行确定第一、第二和第三志愿。项目资料位于 `docs/projects/`，撰写时应以对应项目的实际要求为依据。

## 2. 竞标书内容

官方说明允许竞标材料包含以下内容，可按项目特点组织：

| 可包含的内容 | 说明 |
| --- | --- |
| 竞标信 / 团队适配说明 | 说明团队为什么适合该项目，以及选择该项目的理由。 |
| 相关经验或个人简历（CV） | 展示成员与项目相关的技能、经历及能力。 |
| 初步项目构想 | 提出对项目需求的理解及初步实现思路。 |
| 预计时间安排 | 给出初步的项目阶段与时间规划。 |

**以上是可包含的内容，并非说明中逐项强制要求的章节。** 提供的说明未规定竞标书的页数、字数、固定章节结构或压缩包内文档格式。

## 3. 提交格式与文件命名

### 3.1 提交文件格式

- **每份竞标材料必须打包为一个独立的 `.zip` 压缩文件。**
- 由于 Microsoft Forms 的技术限制，提交前必须在 `.zip` 扩展名后**追加 `.pptx`**，使最终文件名以 `.zip.pptx` 结尾。
- 文件内容仍然是 ZIP 压缩包；这里只是修改文件名以满足上传要求，无需将其转换为 PowerPoint 演示文稿。

### 3.2 命名规则

```text
<TeamID>.<PreferenceNumber>.<ProjectID>.zip.pptx
```

| 字段 | 含义 |
| --- | --- |
| `TeamID` | 小组的正式团队编号。 |
| `PreferenceNumber` | 该项目的志愿序号：`1`、`2` 或 `3`。 |
| `ProjectID` | 项目的正式编号，使用课程项目资料中的完整写法。 |

官方示例：若 `Team202666` 的第一志愿为 `P2026-88`，则文件名为：

```text
Team202666.1.P2026-88.zip.pptx
```

本组的正式 `TeamID` 为 `Team202610`。三个项目的完整 `ProjectID` 及最终志愿顺序仍需在提交前核对；不得直接把上述示例作为本组文件名。

## 5. 项目分配规则

截止后，项目按照以下顺序分配：

1. **处理第一志愿。** 如果某项目仅收到一个小组的第一志愿竞标，该项目自动分配给该小组。
2. **处理第一志愿竞争。** 如果某项目收到多个小组的第一志愿竞标，则评审竞标材料，从中选择一个小组。
3. **依次处理后续志愿。** 第一志愿处理完毕后，对尚未获得项目的小组继续按相同流程处理第二志愿，再处理第三志愿。
4. **分配剩余项目。** 三轮后仍未获得项目的小组，将与剩余项目进行匹配。

**提交了志愿并不保证能获得其中任何一个项目。**
